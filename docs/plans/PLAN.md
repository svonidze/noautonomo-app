# Guided-review с автокурсом и shareable URLs

## Результат

Проверка счёта станет коротким guided-flow: сервис подставляет курс ECB/Banco de España и все безопасно вычислимые поля, пользователь отвечает только на неоднозначные вопросы и один раз подтверждает итог. Все разделы и конкретный счёт получают URL с корректными refresh, Back/Forward и открытием в новой вкладке.

## Изменения

- Создать `fx_reference`-сервис на стандартной библиотеке Python: запрос к ECB `EXR/D.<currency>.EUR.SP00.A`, серверная проверка источника и `Decimal`-инверсия из «валюта за EUR» в используемые приложением «EUR за единицу валюты». Запрос использует дату операции; если курса нет — последнее наблюдение не старше 7 дней с явной фактической датой. Иначе оставляется документированный ручной settlement.
- Расширить `GET /api/review/work-item` объектами `fx_suggestion` и `guidance`: статусы курса (`exact`, `prior`, `existing`, `unavailable`), provenance, автоматические decision-поля, понятные профили решения и только необходимые пользовательские вопросы. Не добавлять новые налоговые правила: неясные IVA/AEAT решения остаются ручными.
- Добавить `POST /api/review/confirm` с packet и выбранным FX. В одной транзакции проверить snapshot и row version, серверно перепроверить официальный курс либо settlement-документ, применить FX, пересобрать packet, наложить полный decision и применить review. При любой ошибке откатить и FX, и решение. Старые FX/validate/apply API сохранить для совместимости, но не использовать в основном UI.
- Выпустить schema v19 для immutable FX provenance: официальный ECB-rate остаётся уникальным, а разные документированные settlement-rates могут сосуществовать; сохранять ссылку на первичный источник, raw observation/hash и связь ручной корректировки с заменённым rate.
- Перестроить UI в `app.js`: факты и автоматически заполненные значения отображать сводно, технические AEAT/cents-поля скрыть по умолчанию, ошибки показать рядом с вопросом, завершение — одной кнопкой «Подтвердить проверку». Отклонение остаётся отдельным действием. Автоматически закрывать только issue-типы, полностью покрытые подтверждёнными ответами.
- Ввести роуты: `/dashboard?period=…`, `/income?period=…`, `/expenses?period=…`, `/review?period=…`, `/review/<transaction-uuid>?period=…`, `/assets`, `/taxes`, `/contacts`. Корень `/` заменяется на канонический dashboard URL после bootstrap.
- Заменить навигационные кнопки и «Открыть проверку» на ссылки с реальным `href`; перехватывать обычные переходы через `pushState`, восстанавливать состояние через `popstate`. Назад из detail ведёт в `/review?period=…`.
- Сервер будет отдавать `index.html` и session cookie только для распознанных SPA-маршрутов; неизвестные URL и `/api/*` сохранят 404. Tailscale allowlist и same-origin защита остаются обязательными: URL — locator, не bearer-token.

## Проверка

- Unit-тесты ECB: точная дата, fallback, лимит 7 дней, неподдерживаемая валюта, timeout/malformed response, точность `Decimal` и отсутствие DB-изменений у GET.
- API/DB-тесты: atomic confirm, stale snapshot, конкурирующая запись, manual settlement, reject без FX, закрытый период и rollback после намеренной ошибки валидации.
- HTTP/Node-тесты: direct deep link, выдача cookie, refresh, Back/Forward, синхронизация периода, malformed/unknown routes и отсутствие fallback для API.
- UI-проверка на 375/768/1440 px, клавиатурная навигация, RU/EN и отсутствие raw tax codes в основном сценарии.
- На production провести только read-only проверку открытого deep link и FX suggestion. Финальное подтверждение реального счёта останется явным действием пользователя.

## Git и выкладка

- Начать из чистого linked worktree на основе актуального `origin/master`: ветка `codex/guided-review-fx-deeplinks`; локальный `master` сейчас отстаёт от origin.
- Не затрагивать исходный worktree и не включать реальные счета, UUID, имена или суммы в тесты/коммиты.
- После pytest, Node-проверок и privacy guard создать Lore-коммиты, запушить ветку и открыть новый **draft GitHub PR** в `master`; PR содержит описание изменений, причины, пользовательский эффект и результаты проверок.
- После CI развернуть точный commit SHA из PR через существующий `ops/deploy.sh`, предварительно создав snapshot SQLite и выполнив migration v19. Не выполнять merge или approve PR автоматически.

## Принятые значения по умолчанию

- Автоматический источник: ECB Data API; подпись в UI — «Справочный курс ECB / Banco de España», не фактический банковский курс.
- Курс предыдущего дня — только предложение с реальной датой и подтверждается вместе с итоговым review.
- Ручная корректировка всегда получает отдельную provenance-запись и не может называться `ecb`.
- Ссылка содержит только opaque transaction UUID, не переносит локальный draft и доступна только авторизованным участникам Tailnet.

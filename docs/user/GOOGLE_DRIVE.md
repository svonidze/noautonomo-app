# Как работает интеграция Google Drive

Google Drive хранит файлы документов. Учетные записи, суммы, статусы и каталог
копий хранятся в SQLite на сервере. Приложение обращается к Google Drive API
напрямую. Добавление файла в Drive само по себе не создает запись в учете.

## Где находятся данные

| Место | Что хранится |
|---|---|
| SQLite | Учетные данные, связи документов с файлами, идентификаторы копий и контрольные суммы |
| Google Drive | Исходные документы и копии загруженных файлов в выбранной папке |
| Локальный архив сервера | Принятые файлы и локальные копии документов |
| Yandex Object Storage | Независимые зашифрованные копии документов и отдельные ежедневные и ежемесячные бэкапы |

Google-файл связывается с документом по постоянному `fileId`. В каталоге также
сохраняются ссылка, имя, размер и контрольная сумма SHA-256, которая позволяет
проверить, что содержимое файла совпадает с принятым оригиналом.

## Два способа добавить документ

### Файл уже находится в Google Drive

В форме новой записи выберите «Google Drive URL» и вставьте ссылку на файл.
Файл должен быть доступен настроенному подключению приложения. Ссылка сама по
себе не предоставляет доступ и не делает документ общедоступным.

Сервер скачивает файл для извлечения данных и проверки содержимого, связывает
полученную запись с исходным файлом в Drive и назначает его основной копией.
Второй файл в Google Drive при этом не создается. Импорт также создает или
проверяет независимую копию в Yandex; ошибка этой проверки означает, что
облачное архивирование не завершено успешно.

Импорт поддерживает PDF, изображения PNG/JPG/JPEG/TIF/TIFF/WebP, CSV и TXT
размером до 30 MB. Проверка ссылки в форме не означает, что любой формат
Google Docs можно импортировать: автоматический экспорт нативных документов
Google в поддерживаемый формат не выполняется.

### Файл загружается с компьютера

Файл сначала принимается в локальный архив. Чтобы сохранить его и в Drive,
нажмите «Выбрать папку Google Drive» и выберите существующую папку архива
через Google Picker. Проверьте название папки в форме перед отправкой файла.

При выбранной папке веб-форма создает или проверяет копии в Google Drive и
Yandex. Для новых файлов в Drive сохраняется понятное имя, а вложенные папки
соответствуют периоду и типу документа.

Без выбора папки веб-форма сохраняет файл локально и не запускает копирование
в Google Drive. Независимое копирование в Yandex затем выполняет настроенное
задание резервного копирования и сверки копий. Его результат нужно проверить
отдельно; локальное принятие файла не подтверждает наличие облачной копии.

Настроенная серверная папка назначения используется операциями хранения,
которые не передают другую папку. Она не подставляется автоматически в новую
веб-форму и не включает отправку всех загрузок в Drive. Приложение также не
обходит папку Drive в поисках новых документов: для учета нужен явный импорт.

Принятый документ поступает на проверку. Сохранение файла, подтверждение данных
и проведение записи являются отдельными действиями; порядок описан в
[учетном процессе](ACCOUNTING_WORKFLOW.md).

## Доступ, открытие документов и резервные копии

Существующий архив может читать отдельное подключение сервисного аккаунта с
правами только на чтение. Новые файлы записывает пользовательское подключение
OAuth с ограниченными правами `drive.file`. Оба подключения могут работать с
одной существующей папкой, но доступ каждого проверяется отдельно. Успешное
чтение сервисным аккаунтом не доказывает, что OAuth-подключение может писать.

Google Picker дает выбрать папку для загрузки. Долгоживущий refresh token
остается в приватном файле на сервере; браузер получает краткоживущий access
token по запросу. Значения токенов и ответы с ними нельзя сохранять в общих
отчетах или репозитории.

При открытии документа приложение проверяет содержимое доступных
зарегистрированных копий по SHA-256. Если подходящей локальной копии нет,
оно пробует основную удаленную копию, затем другие доступные копии по
приоритету чтения. Поэтому документ может открыться из Yandex при недоступности
Drive, если независимая копия существует и ее содержимое успешно проверено.

Копия документа в Yandex и бэкап базы являются разными материалами
восстановления. Статус прошедшей загрузки не заменяет проверку восстановления.
Подробнее: [настройки и наблюдаемые статусы бэкапов](ACCOUNT_SETTINGS.md) и
[восстановление сервиса](../../ops/docs/DISASTER_RECOVERY.md).

## Если сохранение или доступ не работают

Если чтение архива работает, а загрузка не работает, оператор отдельно
проверяет OAuth-подключение, явный режим `credential_mode: oauth` и права записи
в выбранную папку. Ошибка HTTP 404 для папки может означать отсутствие доступа
у этого подключения; она не доказывает, что ваша папка исчезла.

Для существующего архива сначала выберите нужную папку через Picker и проверьте
доступ. Создание другой папки не исправляет доступ к исходному архиву.

Ошибка облачного сохранения может появиться уже после локального принятия
документа. Сначала проверьте, появилась ли запись в системе, и передайте
оператору результат. Повторно импортировать документ только ради исправления
хранилища не нужно.

Настройка подключений и диагностика описаны в
[технической инструкции](../../ops/docs/PROVISIONING.md#google-drive-storage-choices).
Названия, ссылки и результаты проверки конкретного продового архива хранятся
в приватном описании установки, отдельно от этого репозитория.
